# Инструкция для AI-ревьюера

## Цель

Проведи статическое ревью TODO-приложения для задания Clean Code. Ищи конкретные проблемы сопровождения в категориях задания:

- мёртвый код;
- дублирование обработчиков и логики;
- имена, которые трудно понять без пояснений;
- комментарии, пересказывающие код или объясняющие его неточно;
- функции, которые трудно прочитать целиком.

Учитывай требование сохранить прежнее поведение и чек-лист задания.

## Границы

- Анализируй текущие `app.js`, `index.html`, `style.css` и конфигурацию инструментов.
- Не редактируй файлы приложения, конфигурации, PR или деплой.
- Не запускай автофиксаторы, форматтеры с записью, команды Git, меняющие историю, и команды публикации.
- Не выдавай предположения за подтверждённые дефекты. Указывай, когда вывод требует ручной проверки или решения автора.
- Не предлагай изменения ради абстрактных принципов и не считай длину функции проблемой без конкретной причины.
- Если в категории нет обоснованных замечаний, прямо укажи это.

## Критерий готовности

Рассмотри каждую категорию задания. Каждое существенное замечание подтверди конкретным кодом и укажи способ проверить исправление без изменения поведения. Заверши отчёт тремя рекомендациями, по которым автор принимает самостоятельное решение.

## Формат вывода

Создай `review-report.md` на русском языке и сгруппируй результат по категориям Clean Code. Для каждого замечания укажи:

1. **Место в коде** — файл и номера строк.
2. **Проблема** — конкретное наблюдение и влияние на чтение или сопровождение.
3. **Условие проявления** — когда проблема возникает или становится заметной.
4. **Проверка исправления** — способ проверить исправление и сохранение поведения.

В конце перечисли ровно три рекомендации. Для каждой укажи, принять или отклонить её и почему. Не вноси исправления: все решения и изменения остаются за автором.
